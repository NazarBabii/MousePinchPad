# MousePinchPad

[English](README.md) | **Українська**

**Pinch-зум як на трекпаді та комбінації на правій кнопці для будь-якої мишки у Windows 11.**

Скрипт AutoHotkey v2, який перетворює праву кнопку мишки на "шар керування": поки вона затиснута, колесо й інші кнопки виконують додаткові дії. Головна з них — плавний **pinch-зум, як на трекпаді**, а не звичайна зміна масштабу сторінки через Ctrl+колесо.

## Навіщо

Розширення для браузера і більшість програм для мишок "зумлять" через Ctrl+колесо. Це змінює масштаб сторінки, і вона перебудовується. Pinch на трекпаді працює інакше: збільшується саме зображення, як на телефоні, а сторінка лишається як є.

MousePinchPad створює віртуальний Precision Touchpad і робить на ньому справжній pinch двома пальцями, тож Chrome, Edge та інші програми з підтримкою жестів отримують справжній жест трекпада.

## Можливості

| Комбінація | Дія |
|---|---|
| Права кнопка (сама) | Звичайний правий клік, контекстне меню |
| Права + колесо вгору / вниз | Pinch-зум + / − (центр зуму під курсором) |
| Права + бокове колесо вправо / вліво | Гучність + / − |
| Права + натиснути колесо | Пауза / відтворення |
| Права + кнопка "вперед" / "назад" | Перемикач вікон (як Alt+Tab) вперед / назад. Відпусти праву кнопку, щоб вибрати вікно |
| Права + ліва (коротко) | Показати робочий стіл (Win+D), повторно повертає вікна |
| Права + ліва (утримати ~0.8 с) | Заблокувати ПК (як Win+L) |

## Вимоги

- **Windows 11** з підтримкою `CreateSyntheticPointerDevice2` (API віртуального тачпада). Швидка перевірка:
  ```ahk
  h := DllCall("GetModuleHandle", "Str", "user32", "Ptr")
  MsgBox DllCall("GetProcAddress", "Ptr", h, "AStr", "CreateSyntheticPointerDevice2", "Ptr") ? "Є" : "Нема"
  ```
  Документація Microsoft досі позначає це API як попередню версію, тож воно може змінитися.
- **AutoHotkey v2, 64-bit**: [autohotkey.com](https://www.autohotkey.com/)

## Встановлення

1. Встанови AutoHotkey v2.
2. Завантаж `MousePinchPad.ahk` і запусти подвійним кліком. У треї з'явиться зелена іконка **H**.

**Автозапуск з Windows:** `Win+R` → `shell:startup` → поклади туди ярлик на скрипт.

## Використання

Права кнопка по іконці **H** у треї:

- **Reload Script**: застосувати зміни після редагування
- **Suspend Hotkeys**: тимчасово вимкнути (права кнопка працює як звичайно)
- **Exit**: зупинити скрипт

Редагування: права кнопка по файлу → **Edit script** (або будь-який текстовий редактор), зберегти, потім **Reload Script**.

Видалення: **Exit**, прибрати ярлик із `shell:startup` (якщо додавав) і видалити файл. MousePinchPad не змінює жодних системних налаштувань.

## Налаштування

На початку скрипта:

| Параметр | За замовч. | Що робить |
|---|---|---|
| `ZOOM_STEP` | 1.3 | Наскільки зумить 1 клік колеса. Більше — швидше |
| `SMOOTH_MS` | 30 | М'якість руху, мс. Більше — плавніше, але з більшою "інерцією" |
| `FRAME_MS` | 4 | Інтервал між кадрами жесту, мс |
| `SLOP` | 150 | Поріг розпізнавання жесту. Зум не стартує з першого кліку — збільш; стартує ривком — зменш |
| `HOLD_MS` | 30 | Скільки "пальці" стоять нерухомо перед тим, як їх підняти |
| `MOVE_PX` | 15 | На скільки px зсунути курсор, щоб центр зуму переїхав. Центр "стрибає" від тремтіння руки — збільш |
| `IDLE_MS` | 1500 | Через скільки мс після зуму прибрати віртуальний тачпад із системи |

Тривалість утримання для блокування — число в `KeyWait("LButton", "T0.8")`.
Щоб змінити напрямок гучності, поміняй місцями `Volume_Up` і `Volume_Down`.

## Як це працює

**Зум.** Скрипт створює віртуальний Precision Touchpad у режимі "тільки жести" (`SDCO_TOUCHPAD_GESTURE_ONLY`) і подає на нього два "пальці", які розходяться або сходяться. Для Windows і браузера це той самий pinch, що й зі справжнього трекпада, тому:

- збільшується зображення, а не масштаб сторінки;
- курсор не ховається, кліків і тапів не буває: такий тачпад фізично не вміє клікати.

Колесо лише зсуває "ціль" зуму, а окремий цикл плавно підтягує до неї пальці з подвійним згладжуванням, тому кліки колеса зливаються в один безперервний рух. Зум рахується в логарифмах, тож кожен клік дає однаковий приріст масштабу.

Віртуальний тачпад існує тільки під час зуму і ще `IDLE_MS` після нього. Між зумами він не заважає справжньому трекпаду, а видалення пристрою гарантовано знімає "застряглі" пальці.

**Перемикання вікон** — вбудовані дії AutoHotkey `AltTab` / `ShiftAltTab`, де права кнопка грає роль затиснутого Alt.

**Блокування** викликає `LockWorkStation`. `Send "#l"` не працює, бо Windows ігнорує програмно надіслане Win+L.

## Обмеження

- Pinch працює в програмах, які розуміють жести трекпада (Chrome, Edge тощо). Програми без такої підтримки зум не отримають.
- Поки під час зуму затиснута права кнопка, справжній трекпад не реагує: віртуальні пальці "стоять" на віртуальному тачпаді.
- Перетягування правою кнопкою (жести мишкою в інших програмах, виділення правою) не працює, бо правий клік спрацьовує при відпусканні.
- Під час довгого безперервного зуму або коли курсор переїжджає на нове місце буває коротка пауза, поки віртуальні пальці "перехоплюються".
- У вікнах, запущених від адміністратора, скрипт працює, тільки якщо його теж запущено від адміністратора.
- Не запускай паралельно інші скрипти, які перехоплюють праву кнопку: спрацює лише той, що запущений останнім.

## Проблеми

| Симптом | Що робити |
|---|---|
| "Не вдалось створити віртуальний тачпад" | Твоя Windows не підтримує API (див. Вимоги) |
| Тултіп `InjectSyntheticPointerInput: помилка ...` | Запиши код помилки й перезапусти скрипт |
| Зум не стартує з першого кліку | Збільш `SLOP` |
| Бокове колесо чи кнопки нічого не роблять | Їх перехоплює фірмовий софт мишки (Logi Options+, Razer Synapse тощо). Поверни в ньому стандартні дії |
| Сторінка розмита або трекпад не працює після зуму | Відпусти праву кнопку й зачекай ~1.5 с. Якщо не минає — **Exit** скрипта |
